# Архитектура BotPlus AT

## Границы компонентов

| Каталог | Ответственность |
|---|---|
| `Commands` | Регистрация прежних команд AutoCAD, выбор объектов, запросы пользователю, открытие окон |
| `Services` | Операции с DWG, расчёты, подготовка печати, XLSX и PDF |
| `UI` | Общий каталог команд, кеш иконок, лента, классические меню/панель, контекстное меню и тема окон |
| `ViewModels` | Состояние окон и команды интерфейса |
| `Models` | Параметры операций и данные |
| `Infrastructure` | Атомарная запись файлов и ограниченный локальный журнал ошибок |
| `ExcelRuntime` | Изолированная работа с ClosedXML/Open XML без ссылок на AutoCAD |
| `tests` | Автономные регрессии и проверки в настоящем AutoCAD |

Команды и существующие имена блоков сохранены для совместимости с рабочими DWG, макросами и настройками пользователя. Новый контейнер зависимостей не вводился: для текущего размера проекта достаточно явных конструкторов и небольших компонентов.

## Правила выполнения

- API AutoCAD вызывается в основном потоке приложения. Перед модельными изменениями из окон/Idle используется `DocumentLock`; изменения объединяются транзакцией.
- Частые уведомления выделения только помечают данные устаревшими. Расчёт выполняется на Idle с интервалом не менее 100–150 мс и пропускается во время команды AutoCAD.
- Запуск и остановка дополнительных сервисов независимы. Ошибка одного компонента не должна оставлять остальные компоненты без завершения. Все подписки Excel и ограничений копирования снимаются при завершении приложения.
- Окно суммы хранит именно тот документ, на события которого подписано, и меняет подписку при активации другого DWG. `Dispose` идемпотентен; финализатор у управляемой модели окна отсутствует.
- Длительные сетевые запросы не работают в событиях выделения. У обновлений остаются тайм-аут, проверка при запуске и повтор через 24 часа.

## Геометрия и скорость

`CurveGeometry` содержит общий расчёт длины для окна и индикатора. Окружности учитываются в подробном окне и исключаются из индикатора, как в первоначальном задании. Пустые, удалённые и неподдерживаемые объекты пропускаются; NaN и бесконечности не попадают в результат.

`SelectSimilarService` заранее группирует образцы по обязательным типу и слою и проверяет принадлежность исходной выборке через `HashSet`. Порядок обхода результата и смысл включённых фильтров сохранены. Измеренная скорость относится к конкретному тесту, а не ко всем возможным DWG.

`MTextFormatting` разбирает управляющие коды без цепочки регулярных выражений. Перенос `\\P` отличается от настройки абзаца `\\p`; экранированные слеши/скобки и некорректные последовательности сохраняются. Поиск разделителей не выполняется заново по всему оставшемуся тексту.

`NumberingService` отделён от диалога и допускает проверку порядка, разных типов текста и отката при переполнении номера. `CopyService` использует глубокое клонирование AutoCAD для объектов с принадлежащими им атрибутами и данными динамического блока.

## Файлы и внешние приложения

Настройки сначала записываются и сбрасываются на диск во временный файл в том же каталоге, затем заменяют основной файл. При неуспешной записи прежний файл остаётся доступным. Неверные масштабы и номера перечислений нормализуются.

Для Excel данные таблицы сначала читаются в `TableWorkbookData`; работа с XLSX не держит транзакцию DWG. Обратный импорт выполняется только в активный свободный документ. Параллельные сеансы разных таблиц одного документа независимы; повторное открытие уже редактируемой таблицы блокируется. Проверка файлов выполняется раз в секунду. Поддерживаются редакторы с блокировкой файла и редакторы без неё: сохранение должно стабилизироваться на две секунды. При ошибке XLSX сохраняется для восстановления. Импорт ограничен 2 000 000 ячеек до выделения массива данных.

XLSX-реализация собрана отдельным проектом `ExcelRuntime` на .NET 8, пригодным также для хоста .NET 10. Основная сборка создаёт собственный `AssemblyLoadContext`; зависимости загружаются из подкаталога `ExcelRuntime`. Через границу передаются только строки, массивы и числа. Это исключает привязку ClosedXML к одноимённым сборкам хоста или других плагинов. Сборка bundle копирует весь runtime; сборщик лицензий читает оба графа NuGet. Отдельная команда импорта ограничивает создание DWG-таблицы 100 000 ячейками.

Классическое меню и панель используют ActiveX полного AutoCAD и общий `CommandCatalog`. Core Console пропускает этот компонент. Окна используют палитру `COLORTHEME`; оболочка прокручивает содержимое вертикально, таблицы сохраняют собственную горизонтальную прокрутку.

## Публикация PDF

Две команды подготовки DSD используют один `DsdFileWriter`. Базовую структуру пишет `DsdData.WriteDsd`; настройки именованного листа и источник DWG восстанавливаются явно, затем результат проверяется чтением через AutoCAD. Для путей и названий на разных языках используется UTF-16 LE, поддерживаемый Windows INI. Схема работы основана на [документации Autodesk по публикации](https://help.autodesk.com/cloudhelp/2025/ESP/OARX-DevGuide-Managed/files/GUID-B08B5173-0C17-4663-BD1C-A40E4C8F3A75.htm); необходимость восстановления NPS также описана в [примере Autodesk для модельных видов](https://blog.autodesk.io/publishing-model-views-to-a-multi-sheet-dwfpdf/).

Задание публикации хранит снимок листов, ожидает освобождения PDF драйвером и не возвращает системные переменные поверх чужого изменения. Отмена и закрытие документа завершают подписки. Синхронный выпуск через настоящий драйвер проверяется автоматически; полное взаимодействие очереди фоновой публикации с интерфейсом проверяется отдельно.

## Диагностика

`%LOCALAPPDATA%\BotPlusAutocadTool\Logs\plugin.log` содержит дату UTC, операцию и исключение. При достижении 1 МиБ журнал переносится в `.previous`; хранится один предыдущий файл. Журнал локальный и не отправляется автоматически. Сбой записи журнала не прерывает AutoCAD. Каталог доступен из окна «О программе».

Для изолированной проверки или управляемого развёртывания переменная процесса `BOTPLUS_DATA_DIRECTORY` задаёт другой каталог данных. Тестовый сценарий передаёт её только дочернему Core Console, создаёт настройки с отключённой сетью и восстанавливает окружение после выхода. Настройки рабочего сеанса пользователя в тесты не подставляются.

## Проверки и изменения

Быстрая проверка: `scripts/Test.ps1`. Полная доступная автоматизация AutoCAD 2026: `scripts/Test.ps1 -Native -Year 2026`. Core Console работает с отдельным профилем и копией тестового DWG в `artifacts/validation`; библиотека `Assets/WM_FORMAT.dwg` не передаётся хосту как рабочий документ.

Новые изменения должны сопровождаться проверкой изменившегося поведения. Компиляция, расчёты, файловый обмен, компоновка WPF и визуальная работа в полном AutoCAD — разные уровни проверки. Результат на одном уровне не выдаётся за результат на другом; фактические данные находятся в `VALIDATION.md`.
