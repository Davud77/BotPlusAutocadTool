Проверки Core Console выполнялись в отдельном процессе, на временной базе данных. Открытые пользовательские чертежи не изменялись. Изменение SECURELOAD касалось только отдельного тестового процесса; плагин и установщик не отключают защиту AutoCAD.

PDF-тест использует настоящую библиотеку iText и тот же файл `PdfPostProcessingService.cs`, что и плагин. Тестовые типы `Editor` и `BatchPlotItem` изолируют эту проверку от нативного API; она подтверждает преобразование PDF, но не запуск печати из AutoCAD.

Проверка штампа использует настоящую модель представления и тестовое хранилище `IAutoCADService`. Она проверяет разбиение/объединение строк, но не сохранение свойств в реальном DWG.

## Что ещё проверить в полном интерфейсе AutoCAD

- Лента, окна и привязки элементов управления.
- Загрузка в установленных AutoCAD 2025 и 2026; сейчас доступны их compile-only API, а не сами приложения.
- Публикация из DWG через `-PUBLISH`, включая фоновой режим, события завершения, отмену и восстановление системных переменных. Автоматический тест проверил постобработку, но не весь цикл работы штатного PDF-драйвера.
- Форматы A0–A4 и кратные, реальные рамки, поворот и масштаб 1:1.
- Экспорт/отложенный импорт Excel с установленным редактором, изменение размеров и объединений таблицы.
- Подготовка DWG для заказчика, очистка, выбор по образцу, нумерация, аксонометрия и мультикопирование на характерных чертежах.
- Установка, обновление и удаление будущего EXE — следующий отдельный этап.

## Повторяемые команды

Из корня проекта:

```powershell
.\scripts\Verify-Structure.ps1
dotnet build .\BotPlusAutocadTool.csproj -c Release -p:AutoCADVersion=2025
dotnet build .\BotPlusAutocadTool.csproj -c Release -p:AutoCADVersion=2026
dotnet build .\BotPlusAutocadTool.csproj -c Release -p:AutoCADVersion=2027
dotnet run --project .\tests\PdfChecks\PdfChecks.csproj -c Release
.\scripts\Build-Bundle.ps1
```

Для AutoCAD 2027 по умолчанию используется `C:\Program Files\Autodesk\AutoCAD 2027`. Иной путь задаётся `-p:AutoCADPath=...`. Скрипт bundle не устанавливает плагин и каждый раз создаёт новую папку `artifacts/staging`.

`tests/AutoCADSmoke` — отдельная тестовая DLL, она не включается в итоговый bundle. Сначала собирается основной проект 2027, затем тестовый проект. В отдельном Core Console загружаются обе DLL и вызывается `BOTPLUS_SMOKETEST`; успешный результат отмечается строкой `BOTPLUS_SMOKE_PASS`.

Логи этапа 3 сохраняются в общей папке `архив/analysis`; артефакты дальнейших проверок — в `artifacts` проекта.

## Версия 1.1.0

Добавлены нативная панель суммы текущего выделения, фоновая проверка GitHub Releases и ручная команда `BOTPLUS_CHECKUPDATES`. Теперь зарегистрировано 18 имён команд. Мастер установки поддерживает общую установку и установку текущему пользователю с разными правильными путями `ApplicationPlugins`.

Проверка Core Console подтвердила фильтрацию линий/полилиний/дуг, исключение окружностей согласно исходному LISP, пересчёт после изменения геометрии и ноль для пустого набора. Сохранены прежние проверки текста и штампа. Отдельные тесты обновлений проверяют сравнение версий, предварительные выпуски, черновики, недопустимые URL и отсутствие новых выпусков. Сборки 2025/2026/2027 проходят без ошибок и предупреждений.

Нативная панель и диалог уведомления реализованы через API AutoCAD, но их положение и внешний вид в полном интерфейсе ещё требуют визуальной проверки. Core Console подтверждает вычисления, а не видимость панели рядом с переключателем модели/листов.

## Версия 1.1.1

Панель суммы вставляется первым элементом строки состояния. Создание ленты повторяется после её готовности и восстановления рабочего пространства; каталоги зависимостей зарегистрированы через `AssemblyMappingFolder` и `SupportPath`. Расписание проверяется отдельными тестами: каждый новый сеанс и повтор через 24 часа.

Установщик удаляет прежнюю версию через зарегистрированную команду удаления, учитывая имена `unins000.exe`, `unins001.exe` и т.д. Удаление ограничено выбранным режимом и каталогом продукта; файлы настроек находятся вне bundle.

На втором ПК с AutoCAD 2026 пользователь сообщил об отсутствии обоих элементов интерфейса. Точная версия AutoCAD и ошибка загрузчика пока недоступны, поэтому устранение этой конкретной ситуации не считается подтверждённым. Для сбора сведений добавлен read-only скрипт `scripts/Get-LoadDiagnostics.ps1`; полный интерфейс 2026 необходимо проверить повторно.

## Версия 1.2.0

Вкладка переименована в BotPlus AT; добавлена команда `BOTPLUS_INSERTFORMAT`. Проверка реального пользовательского файла `WM_FORMAT.dwg` в Core Console подтвердила наличие одноимённого определения, динамический тип блока и 51 неконстантный атрибут. Проверены клонирование определения, непустая геометрия, вставка в заданную точку на слой WM_FORMAT и повторное использование определения без дубликатов. Теперь зарегистрировано 19 имён команд.

DWG включён в обе линии установочного пакета. Исходный файл пользователя не изменялся; копия в Assets имеет SHA-256 `ae4c22e660706f53ceb3c0b92a314091c015e5b39a19e94436e1407957c31938`. Предпросмотр/выбор точки и визуальное отображение атрибутов в полном интерфейсе AutoCAD требуют пользовательской проверки; автоматический тест проверяет базу данных и геометрию.

## Версия 1.2.1

Получен журнал из AutoCAD 2026 с DLL 1.1.1: `SettingsService` не мог загрузить `System.Text.Json, Version=9.0.0.0`, а обращение к настройкам вне `try` в обработчике Idle повторяло исключение. Настройки и разбор GitHub переведены на поставляемую Newtonsoft.Json. Защищены создание папки настроек и весь обработчик Idle; при неожиданном сбое он отключается до перезапуска, сетевые ошибки остаются штатно обрабатываемыми.

- Регрессии реальных исходников сервисов проходят на .NET 8 и .NET 10: старый JSON и UTC-дата, неизвестное поле, повреждённый JSON, недоступная папка, сохранение, выбор безопасного выпуска, расписание, ошибка сети и отключение сбойного Idle без модального окна. Граница API AutoCAD в этих тестах заменена заглушкой.
- Дополнительно пройден настоящий AutoCAD 2026 Core Console, CLR 8.0.31: чтение настроек, разбор JSON GitHub и отсутствие прямой ссылки DLL на System.Text.Json. Проверена и DLL из установочного bundle для 2025–2026, собранная против API 2025. Все 19 команд, расчёт длины, текст, штамп и импорт динамического WM_FORMAT с 51 атрибутом проходят.
- Те же smoke-проверки проходят в AutoCAD 2027 Core Console, CLR 10.0.12. Сборки профилей 2025/2026/2027 завершены без ошибок и предупреждений; smoke-модуль для установленного API 2026 имеет два предупреждения MSB3277 о транзитивных версиях библиотек хоста, но загружается и проходит проверку в этом хосте.
- EXE проверен в изолированном каталоге: установка 1.1.1, переход на 1.2.1 с запуском прежнего деинсталлятора, очистка устаревшего файла, удаление и сохранность пользовательских настроек. Первоначально прерванная сборка EXE была заменена завершённой сборкой; публикуется проверенный итоговый файл.

Полный интерфейс AutoCAD 2026 (видимость ленты/индикатора и работа всех окон) остаётся отдельной пользовательской проверкой. Исправление конкретного исключения подтверждено в его версии CLR и в самом Core Console, а не только компиляцией. Транзитивная зависимость iText от System.Text.Json по-прежнему поставляется в bundle для PDF; настройки и обновления её не используют.
